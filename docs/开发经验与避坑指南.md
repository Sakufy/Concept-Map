# 开发经验与避坑指南

> 本文件沉淀本项目从开发到上线的**全部踩坑经验**，按环节分类。每条经验给出：现象 → 根因 → 解法 → 预防。
> 面向对象：AI 助手 + 人类开发者。**动手前先翻本文件对应章节**，避免重复踩坑。
> 维护：新踩坑一律先补当日 memory/CHANGELOG，再有价值则提炼进本文档对应章节（避免只写流水账）。

## 一、开发环境与依赖

| 坑 | 现象 | 根因 | 解法 / 预防 |
|---|---|---|---|
| vitest 版本 | vitest 2 与 vite 6 类型冲突 | 版本矩阵不兼容 | 锁定 **vitest 3.2.7**（已固定，勿擅自升级） |
| ESLint | `npm run lint` 不可用 | 项目无 ESLint 依赖 | 需要引入前先问用户，不擅自加依赖 |
| 构建体积 | 主 chunk 690KB+ 有 warning | 未分包 | 按需 `React.lazy` + 动态 `import()`；已处理，勿回退 |
| Supabase 拒绝 example.com 注册 | 注册 400 `Email address "x@example.com" is invalid` | GoTrue 默认阻止 example.com 等域名（防垃圾） | 自测注册用普通域名（如 `@qq.com`）；错误中文化映射 `is invalid` → 「邮箱格式不正确」 |
| 注册确认邮件限流 | 注册 429 rate limit（「操作过于频繁」） | 未配置自定义 SMTP，内置邮件服务限流 | 真实收信验证需在 Supabase 配 SMTP；前端对限流错误做中文化兜底 |
| resend API 命名 | `supabase.auth.resendEmail` 报 TS 不存在 | supabase-js 2.112.3 无该方法 | 用官方 `supabase.auth.resend({ type:'signup', email })` |

## 二、React Flow / 画布（本项目最高频踩坑区）

### 2.1 事件与交互

| 坑 | 现象 | 根因 | 解法 / 预防 |
|---|---|---|---|
| 双击建节点误触发 | 双击节点会新建新节点 | React Flow v12 无 pane 级 `onDoubleClick`，事件冒泡到 wrapper div | handler 内 `event.target.closest('.react-flow__node')` 排除节点（**凡冒泡事件都要做**） |
| 受控选中不生效 | 选中态无高亮 | 三件事缺一 | ① `onNodesChange` 处理 `select` ② `toFlowNodes` 输出 `selected` ③ 组件 `.selected` class。三者缺一不可 |
| 点击被吞 | 路径模式点节点无响应 | `panOnDrag` + 节点可拖拽时点击被当拖拽预处理，`onNodeClick` 不触发 | 临时禁用 `nodesDraggable`/`panOnDrag`/`selectionOnDrag`（退出模式恢复） |
| 节点在视口外 | dagre 重排后冒烟点击不到 | 布局后视口未跟随 | 冒烟/交互前先 `fitView()`/`setViewport` |
| 空画布 fitView 放大 | mount 时视图拉到 maxZoom，节点重叠 | fitView 对空画布取放大上限 | 选中边改用 `dispatch('click')` 到 `.react-flow__edge`，绕开 HTML 遮挡 |

### 2.2 渲染与订阅（最难的一类坑）

| 坑 | 现象 | 根因 | 解法 / 预防 |
|---|---|---|---|
| **nodeLookup 永不触发重渲染** | edges 永远拿不到测量/位置更新 | React Flow v12 的 `nodeLookup` 是**原地 mutate**（`adoptUserNodes` clear+重填、`updateNodeInternals` set 新对象），Map 引用恒不变 → zustand `Object.is` 等值比较永远 equal | 选择器返回 **`Array.from(s.nodeLookup.values())` 新数组 + `zustand/shallow`** 逐元素比较（照搬官方 `useNodes`/`useInternalNode` 模式） |
| 节点自适应 | 文字变化框不跟随 | 手写尺寸逻辑 | **不传 width/height → React Flow ResizeObserver 自动测量**（官方成熟模式）；`min/max-width/height` 定边界；**勿与 `NodeResizer` 同用**（冲突） |
| 首屏 fitView 错位 | 0 尺寸节点算错视口 | 测量异步完成 | `useEffect` rAF 轮询「等全部 `getInternalNode(id).measured.width>0` 再 `fitView({padding:0.1})`」 |
| 数据尺寸过期 | `p.w/p.h` 与实测不符 | 自适应后数据层尺寸成为历史遗留 | 命中/边界判断一律用 `getInternalNode(id).measured` |
| `EdgeLabelRenderer` jsdom null | 组件测试报错 | 依赖 DOM portal | 测试中 mock 为 `<>{children}</>` |
| Handle 报错 `error#001` | 组件测试崩溃 | Handle 缺 provider 祖先 | 测试包 `<ReactFlowProvider>` |
| `getBezierPath` 不支持自定义控制点 | 无法用控制点 | 官方 API 无该参数 | 手写 path：直线 `M sx,sy L tx,ty` / 贝塞尔 `M P0 C P1 P2 P3` |
| 徽标位置 | 线上标签不在中点 | 用错了公式 | 直线取 `(sx+tx)/2,(sy+ty)/2`；贝塞尔用 t=0.5 公式 |

### 2.3 几何与布局

| 坑 | 现象 | 根因 | 解法 / 预防 |
|---|---|---|---|
| 端点吸附 | 连线穿过节点或不在最短处 | 固定 Handle 位置 | `findClosestEdgePoints`（slab 法射线-矩形求交）：两矩形中心连线方向发射线求第一交点；中心重合兜底。CS 经典算法，无现成库函数，已自研并记录原因 |
| 连词布局概念边缺失 | dagre 重排后某概念成孤立 | `lpPairs` 存储时 `?? ''` 把 null 占位强转空串，第二段永远填不上 | **保留 null 占位**，不做空串强转 |

## 三、状态管理（Zustand + zundo）

| 坑 | 现象 | 根因 | 解法 / 预防 |
|---|---|---|---|
| 视图态进了撤销历史 | Ctrl+Z 撤销了不该撤销的 | partialize 没过滤 | `partialize` **只快照 doc**；纯视图态（pathMode/选中/编辑态）用 `set()` 直接写 |
| 拖一次节点吃掉几十步历史 | 无法撤销久远操作 | 每次 position change 都产生快照 | `onNodeDragStart` pause + `onNodeDragStop` resume 合并成一步（zundo 记「set 前状态」） |
| store 快照过期 | `addConnection` 后查不到 viaId | 闭包持旧快照 | 冒烟/异步回调里**重新 `getState()`** 再查询 |
| `React.lazy` 报 `Cannot convert object to primitive value` | 懒加载组件崩 | lazy 默认取 `default` 导出，本项目是命名导出 | `.then((m) => ({ default: m.X }))` |

## 四、测试与浏览器冒烟（Playwright / vitest）

### 4.1 Playwright CLI（`playwright-cli`）

| 坑 | 现象 | 根因 | 解法 / 预防 |
|---|---|---|---|
| 内联文件路径 | 报 `smoke is not defined` | `run-code` 把文件名当代码 | **必须 `run-code --filename <path>`** |
| `page.on('dialog')` 冲突 | 报 `does not handle the modal state` | 与工具 modal state 打架 | `page.evaluate(() => { window.confirm = () => true; })` 页面内覆盖；遗留 dialog 先 `playwright-cli dialog-accept` |
| `selectOption(ElementHandle, opts)` | 报 `selector: expected string, got object` | 包装器不支持 ElementHandle | 用字符串选择器 `selectOption("[data-testid=...]", opts)` |
| 断言文本不准 | button `textContent` 含隐藏 ✎ span | 图标是 span 文本 | 断言更具体子元素（如 `.app-header__title-text`） |
| 中文选择器/文案乱码 | 选择器找不到 / 断言失败 | Windows 下 CLI 传中文被 GBK 转码 | **用纯 ASCII 选择器**；需要中文断言时读 DOM 真实值（如 `textContent` 返回）比较，不在命令串里写中文 |
| PowerShell 内联脚本 `$_` 被吞 | 报 `Missing expression after unary operator` | 外层 genie-ps 转义 | 换 `curl.exe -x ...` 等非 `$_` 写法；或 `Out-String` 包裹整段 |
| **run-code 脚本格式** | 报 `SyntaxError: Unexpected token 'const'` | `run-code` 期望**函数表达式**，不是任意脚本 | 冒烟脚本文件写成 `async page => { ... }`（顶层就是函数表达式，见 `smoke-v2-ui.js`），配合 `--filename <path>` 加载 |
| **合成 click 不产生 dblclick** | 冒烟里两次 `page.mouse.click()` 后双击 handler 没触发 | playwright 合成事件不自动生成浏览器级 dblclick（普通 div 对照实验确认） | 模拟双击用 `el.dispatchEvent(new MouseEvent('dblclick', { bubbles: true, cancelable: true }))`（会触发 React 合成事件 + React Flow `onNodeDoubleClick`）；真实用户浏览器双击是正常的，别据此误判产品 bug |

### 4.2 冒烟方法论

- **jsdom 不渲染 edge**（依赖节点尺寸异步测量）→ 连线/边相关行为用 playwright 实测，不写死 jsdom 集成测试。
- **诊断拖线/点击失败**：先 `document.elementFromPoint(x,y)` 打命中链，区分「测试坐标问题」与「产品 bug」——很多"bug"其实是脚本坐标不对。
- **dev 冒烟设施**：dev 模式在 `window.__cmapStore` 暴露 store（`import.meta.env.DEV` 条件），冒烟脚本直接构造数据 + `setViewport`，避免 UI 长链路。
- **移动端触摸**：合成 PointerEvent 无效，需 CDP `setTouchEmulationEnabled` + `dispatchTouchEvent`。
- **连线样式断言**：stroke/stroke-width 是 CSS 属性，用 `getComputedStyle`。
- **LP 节点 DOM class**：`react-flow__node-linkingPhrase`（不是 `-lp` 后缀）。
- 冒烟脚本统一命名 `smoke-*.js`，已被 `.gitignore` 排除，截图同名前缀。
- **后台启 dev server 冒烟**：`Start-Process -WindowStyle Hidden npm.cmd run dev` + `-RedirectStandardOutput/-RedirectStandardError` 日志；6s 后 `curl -s -o NUL -w "%{http_code}" http://localhost:5173` 探测 200 就绪再开浏览器。结束记得杀进程。
- **线上 build 版无 `__cmapStore`**：dev 冒烟设施只在 `import.meta.env.DEV` 暴露；线上版用 `page.mouse.dblclick(x, y)` 直接建节点（配合 `page.evaluate` 拿坐标），不需要 store 直改。空图整理按钮 disabled → 先建节点再点。
- **IndexedDB 恢复旧数据干扰断言**：dev 冒烟页面会从 IndexedDB 恢复上一轮保存的旧数据（如旧色节点），按「新样式色值」断言节点会失败——不是产品 bug。**按唯一文本定位新创建的节点**（如建节点时用 `V2Accent` 前缀）再断言样式。
- **hover 色 ≠ base 色**：`page.click()` 后鼠标停留在按钮上触发 hover 样式，与点击后的 active/base 样式不同，断言颜色类会不稳定 → 断言放宽为两种蓝系，或先 `page.mouse.move(2,2)` 移开再取值。
- **React Flow Panel 定位用 margin 不是 top/left**：`@xyflow/react` 的 `Panel` 组件用 `.react-flow__panel { position: absolute; z-index: 5; margin: 15px; }` 定位，`computedStyle.top === '0px'`（不是 10/15px），视觉偏移靠 margin。冒烟断言「Panel 在 top-left」用 `getBoundingClientRect().left/top` 验证视口位置（`r.left < 40 && r.top < 120`），不要断言 `cs.top === '10px'`。
- **contentEditable 节点编辑态必须填回文本**：编辑态 JSX 常用 `{!editing && data.text}`（编辑时渲染空），useEffect 必须 `el.textContent = data.text` 填回原文 + **rAF 重试 focus**（React Flow 节点测量前 `visibility:hidden`，focus 无效，最多重试 30 次）。`ConceptNode` 有完整实现；`LinkingPhraseNode` 曾缺这两步 → 用户双击连词后文本框空白（误以为无法输入）。照搬对齐即可。

## 五、部署上线（CloudBase 静态托管）

### 5.1 标准流程（沉淀为固定步骤）

```
1. npm run build                  # tsc + vite，产出 dist/
2. connect_cloud_service          # IDE 会话令牌
3. envQuery(action=hosting)       # 确认环境与 IndexDocument=index.html
4. uploadFiles(localPath=dist, cloudPath=/)   # 上传整个构建产物目录
5. 验证（见 5.3）
6. 更新 README（在线地址章节）+ CHANGELOG（deployed 记录）
```

### 5.2 核心坑

> **功能开发后必须重新部署！** 用户反馈「线上没有新功能」时，第一个要怀疑的就是**部署时间早于功能开发**——线上一直在跑旧版。

| 坑 | 现象 | 根因 | 解法 / 预防 |
|---|---|---|---|
| `uploadFiles` 相对路径报错 | `路径不存在：C:\Users\Steve\AppData\Local\Programs\CodeBuddy CN\dist` | 相对路径被解析到 IDE 安装目录而非项目根 | **`localPath` 用绝对路径**（如 `d:\AI\概念地图项目\dist`） |

### 5.3 验证线上版本的排查链（按顺序，缺一不可）

```
① 线上 HTML 引用的产物文件名 == 本地 dist 的产物文件名？
      curl.exe -s "https://<域名>/?v=<时间戳>" | findstr assets
      （对比 <script src> 的 hash 文件名）
② playwright 真实打开线上 URL，实测用户场景（重命名/建文件夹/……）
③ 若①②都通过 → 用户侧浏览器旧缓存 → 让用户硬刷新
```

### 5.4 缓存注意

- **SW 是 network-first**（每次刷新先走网络、失败回退 cache）+ `skipWaiting`/`clients.claim` → **用户硬刷新（Ctrl+F5）即拿新版**，无需清站点数据。
- 静态托管 + CDN 缓存：自己验证/分享时**带随机 query**（`?v=<时间戳>`）绕过缓存。

## 六、Git 提交与推送

### 6.1 Windows 中文提交信息乱码

| 坑 | 现象 | 根因 | 解法 / 预防 |
|---|---|---|---|
| 中文 commit message 乱码 | 提交信息变 GBK 乱码 | PowerShell 内联中文被转码 | **必须 `git commit -F <utf8文件>`**（先用 write_to_file 写 UTF-8 的 msg 文件，提交后删除）或纯 ASCII message |
| execute_command 中文路径乱码 | 找不到文件 / 路径不存在 | 命令串中文字被转码 | 命令串避免中文路径/文案；`cd` 后用相对路径 |

### 6.2 GitHub 推送连不上

| 坑 | 现象 | 根因 | 解法 / 预防 |
|---|---|---|---|
| 直连 443 超时 | `Failed to connect to github.com port 443` | 本地网络无法直连 GitHub | ① 探测本机代理：`curl.exe -x http://127.0.0.1:7890 -s -o NUL -w "%{http_code}" https://github.com`（Clash 默认 **7890** 实测可用）② 临时代理推送（**不改 git config**）：`git -c http.proxy=http://127.0.0.1:7890 -c https.proxy=http://127.0.0.1:7890 push origin main` |

> 纪律：**永不修改 git 全局配置**（proxy/user 等），一律用 `-c` 临时参数。

### 6.3 提交规范

- Conventional Commits：`feat:` / `fix:` / `refactor:` / `docs:` / `test:` / `chore:`。
- 提交前 `git status` 确认范围，`git add -A` 前看清 untracked。
- 提交信息文件用完即删（放在 `.git/` 下，不会被 add）。

## 七、用户反馈排查方法论（闭环）

用户反馈「XX 不好用/看不见」时的**标准排查链**（本项目实战验证）：

```
① 本地实现了吗？             — 代码 + 测试（npx vitest run）
② 本地冒烟过吗？             — playwright smoke-*.js
③ 线上重新部署了吗？         — 这是最常见的根因（部署先于开发）
④ 线上文件 = 本地 dist 吗？  — curl | findstr assets 对比文件名
⑤ 线上功能实测过吗？         — playwright 开线上 URL 实测用户场景
⑥ 用户浏览器缓存？           — 让用户硬刷新（Ctrl+F5），SW network-first 无需清数据
```

**功能交付闭环**：开发 → 测试 → 构建 → 部署 → 线上实测 → 通知用户（含刷新指引）→ 提交/推送 → CHANGELOG + memory 留痕。
